# dtg — design token generator

Design decisions as a YAML definition, compiled deterministically into CSS,
Figma variable payloads, and a browsable dev server. Think dbt for design
tokens: the definition file is the models, refs are `ref()`, algorithms are
macros, `emit` is materialization, and the dev server is the docs site.

Unlike token stores (DTCG files, Style Dictionary inputs), the definition
doesn't hold values — it holds *recipes and relationships*. Colors are
generated by named algorithms from a handful of anchors; semantic roles
point at generated steps by reference. Change one parameter and everything
derived regenerates, byte-for-byte reproducibly.

## Commands

```
dtg dev  [--port <n>]                          # browse: ramps, ΔE, lineage; live-reloads on definition save
dtg emit [--live] [--css <path>] [--figma <path>]  # generate CSS + Figma payload; --live re-emits on save
```

Definition resolution: `--definition <file>` if given; else the
`definitions` entry in `dtg.yaml`; else discover `design-tokens/*.dtg.yaml`.
Output defaults land beside the definitions:
`design-tokens/tokens.generated.css` and `design-tokens/figma.json`.

## Project layout

```
design-tokens/
  colors.dtg.yaml          # the definition (decisions)
  tokens.generated.css     # generated, committed, never hand-edited
  figma.json               # generated, committed (see roadmap)
dtg.yaml                   # optional; only needed off-convention
```

`dtg.yaml`, when present:

```yaml
definitions: design-tokens/ # a dir (globs *.dtg.yaml) or an explicit file
outputs:
  css: design-tokens/tokens.generated.css
  figma: design-tokens/figma.json
```

Precedence: CLI flags > `dtg.yaml` > convention defaults.

## The definition file

```yaml
dtg: 1 # grammar version

modes: [light, dark]

systems:
  sky: { algorithm: ink-ramp, base: "#fafdff", ink: "#001a28" }
  theme: { algorithm: oklch-scale, base: "#03a2e8" }
  shadow: { algorithm: overlay, color: "#000000" }
  white: "#ffffff" # statics: plain hex

defaults: # shared params, per algorithm
  oklch-scale:
    toward: ["#fafdff", "#001a28"]
    hueShift: 15
    stops: { "50": 0.05, "500": 1, "950": 0.05 }

core: # any non-reserved top-level key is a section you name;
  surface: #   each section becomes a Figma collection
    canvas: [sky/3, night/0] # one ref per mode
    floating: [surface.card, night/0] # roles can point at roles
  state:
    hover: [transparent(sky/3), transparent(night/3.5)]
  label:
    primary: # omit drops the segment: emits --label
      omit: true
      refs: [night/0, sky/0]
    secondary: [night/30, sky/40] # → --label-secondary
```

Grammar rules:

- `dtg: 1` declares the grammar version; the resolver warns when it's
  missing and refuses versions it doesn't understand.
- **`systems`** declares color systems: `name → { algorithm, ...params }`
  or a plain hex (a static). Reserved keys the tool owns: `algorithm`,
  `emits` (public-name override for emitted tokens), `overrides`
  (selector → hex, pins a step's flattened value). Everything else passes
  through to the algorithm untouched (built-ins reject unknown params, so
  typos fail loudly).
- A **ref** is `system/selector` — everything after the slash belongs to
  the algorithm — or `domain.role` (alias another decision), or
  `transparent(system/selector)` (a step's unflattened ink form).
- **Raw hex is legal only inside `systems`.** The sections tier points and
  derives; every color traces back to an anchor.
- A **role** is a list of refs, one per mode — or `{ refs, alias?, omit? }`
  when its public name diverges.
- **Sections are yours.** Top-level keys other than
  `dtg`/`modes`/`defaults`/`systems` are sections — arbitrary names, each
  emitted as a Figma collection (CSS names never include the section).
  Role paths (`domain.role`) must be unique across sections so refs stay
  unambiguous.
- **`alias`** on any emitting key — system, the systems block itself, a
  section, a domain, or a role — replaces its public name: a string for
  all targets, or per-target (`alias: { css: light, figma: Light }`).
  Internal names are for pointing; public names are for emitting; refs
  always use internal names.
- **`omit: true`** on a domain or role drops that segment from public
  names (`label.primary` with omit → `--label`, beside
  `--label-secondary`). The resolver rejects roles with both segments
  omitted and any public-name collisions aliasing/omission would create.
- The definition is self-describing: with no alias/omit, everything emits
  verbatim. Aliases exist for divergences that are structural (a system
  named `light` would collide with the mode) or historical (shipped names
  older than the definition).

## Built-in algorithms

- **ink-ramp** (`base`, `ink`): ink composited over a base; the selector is
  the ink's alpha percent, so the token name is the recipe. Backs
  `transparent()`.
- **oklch-scale** (`base`, `toward`, `hueShift`, `stops`): a chromatic
  scale blended from the base in OKLCH. Stops below 500 blend toward
  `toward[0]`, above toward `toward[1]`; stop values are the fraction of
  base remaining. Declared stops emit in full (a public palette).
- **overlay** (`color`): color at selector % opacity, never flattened
  (shadows, scrims).

The registry is open: `resolveDefinition(yaml, extraAlgorithms)` merges
project algorithms over built-ins. What kind of value a ref produces is the
algorithm's nature, never a per-role flag.

## Principles

1. Rigidity comes from closed sets, so every set is open — domains, roles,
   systems, params, selectors. Only the plumbing contract is fixed.
2. Determinism is non-negotiable: same definition → same bytes. The
   definition is data; expressions are parsed, never evaluated as code.
3. Explicit over inferred: a role's output is readable from its own line
   plus the primitives block.
4. Demand-driven primitives: an ink-ramp step exists because a ref demands
   it. Declared palettes are the exception.
5. Overrides pin flattened hexes only; exceptions are declared, visible,
   and promotable — never silent.

## Emit targets

- **CSS**: a single generated file with the `@theme` primitives block
  (Tailwind v4), `:root`/`.dark` semantic blocks (step refs stay as
  `var()` chains; transparent/overlay values inline), and `@theme inline`
  utility wiring.
- **Figma**: a deterministic payload (`figma.json`) of collections, modes,
  values, and aliases-by-name — no file IDs — for a courier (agent or
  plugin) to replay against a Figma file via the Plugin API. The REST
  variables API is Enterprise-only; all sync paths run through plugins.

## Roadmap

- Multi-file definitions (`shadows.dtg.yaml`, `type.dtg.yaml` as siblings;
  one resolver over all) — discovery exists, merging doesn't yet.
- Figma payload moves from `emit` to sync-time generation: agreed in
  principle that the payload belongs to the sync loop (ephemeral, generated
  by a future `dtg figma` command whose --dry-run diffs against the live
  file; dev server serves it at /figma.json for a plugin courier). Kept as
  an emit artifact in 0.1 for simplicity.
- `check` command: definition vs emitted artifacts drift, inert overrides,
  longhand-sugar detection.
- Custom algorithm loading from a project path (the resolver API already
  accepts a registry; the CLI doesn't load one yet).
